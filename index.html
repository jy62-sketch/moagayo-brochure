01문제 정의

여행에서 가장 필요한 순간에,
티켓이 열리지 않아요

친구·연인과 자유여행을 준비하면 항공권, 숙소 예약확인서, 교통패스, 입장권, QR 바우처가 여기저기 쌓여요. 모으지 못한 티켓은 현장에서 문제가 돼요.

동행 자유여행의 티켓은 카톡·예약 앱·사진첩·이메일에 흩어져 저장돼요. 그래서 동행자들이 가진 티켓을 한곳에서 함께 보기 어렵고, 현장에서는 인터넷 문제나 저장 위치 혼선 때문에 필요한 티켓을 바로 열지 못해요.

    데스크 리서치와 설문 36명으로 문제를 좁히고, 기능 범위를 정한 기획서(PRD)를 썼어요.

  2. 10.12

    작업 규칙과 화면 시안

    작업 규칙을 먼저 정하고, 코드 전에 클릭해 볼 수 있는 시안 3종을 비교해 디자인을 확정했어요.

  3. 10.12

    기능 구현과 배포

    여행방 → 여행지 → 티켓 항목 → 업로드 → 초대 → 오프라인 저장 순서로, 하나 끝낼 때마다 직접 눌러 보며 만들고 누구나 열 수 있게 배포했어요.

  4. 10.12 ~ 10.13

    실제 기기 확인과 보완

    아이폰 홈 화면 앱에서 저장·연결이 되는지 확인하고, 발견한 문제를 고쳤어요. 연결 코드와 시작 전 안내가 이때 생겼어요.

  5. 10.13 ~

    사용자 테스트 의견 반영

    사용자 테스트에서 나온 의견을 반영하는 중이에요. 안드로이드 실기기 확인도 이어서 해요.

시험 환경에서는 안 보이고 실제 기기나 배포 사이트에서 드러난 문제가 많았어요.

👍 잘한 점

  • 설문 응답마다 대응 기능을 연결해서, 기능 논의가 "내 생각"이 아니라 "응답"으로 끝났어요.
  • 코드 전에 시안 3종을 비교해서 방향을 빨리 정했어요.
  • 용량·형식·권한·잠금 같은 규칙을 화면이 아니라 서버에서 강제하고 자동 점검했어요.
  • 배포 후 실제 아이폰에서 확인해, 시험 환경에서 못 본 문제를 찾았어요.

🤔 아쉬운 점

  • 설문은 20~30대 그룹 34명이라 대표성에 한계가 있어요.
  • 안드로이드 실기기 확인은 아직 진행 중이에요.
  • 봇 방지(CAPTCHA)는 시험 단계라 아직 넣지 않았어요.
  • URL·실시간 갱신형 티켓은 오프라인으로 열 수 없어요.

➡️ 다음에는

  • 기획서 7장 검증: 휴대폰에서 인터넷 없이 열리는지, 등록 상태와 오프라인 상태를 헷갈리지 않는지 확인해요.
  • 사용자 테스트 의견 반영, 공개 전 봇 방지 적용.
  • 2단계 후보: 참여자 관리, 전체 티켓 보관함, 파일 검색, 알림.

🧭 배운 점

  • 시험 환경과 실제 기기는 달라요. 아이폰 Safari와 홈 화면 앱은 저장 공간이 따로라는 사실은 실제로 써 보고서야 알았고, 그 덕에 연결 코드가 생겼어요.
  • 한계는 숨기지 않는 게 신뢰예요. 오프라인으로 못 여는 티켓은 못 연다고 화면에 적었어요.
  • 결정을 적어 두면 바꾸기 쉬워요. 비밀번호 저장 방식을 정정하고 Figma 계획을 접을 때, 기록이 있어서 이유를 바로 설명할 수 있었어요.

🤝 AI와 일한 방식

Claude Code에게 처음에 정해 준 규칙이에요.

  • 기획서(spec)는 제가 쓰고, 허락 없이 고치지 않아요. 바꿀 때는 먼저 어떻게 바꿀지 보여 주고 허락을 받아요.
  • 중요한 결정은 날짜·내용·이유·다른 선택지를 결정 로그에 남겨요.
  • 큰 결정은 혼자 정하지 않고 먼저 물어봐요.
  • 커밋과 GitHub 업로드는 제가 말할 때만 해요. API 키는 코드에 쓰지 않아요.
